# V2 升级问题处理

> 跟踪 OpenMate 在 opencode **v2** 下暴露的工具展示/交互与滚动问题。
> 前置：项目已声明只支持 opencode v2，**不再兼容 v1**。
> 验证方式：Docker（Bridge + opencode v2）+ Android 模拟器端到端。

## 一、问题清单

### P1 工具展示与交互（V2）
V1 → V2 工具结构变化导致渲染错位，需统一按 V2 处理：

| 项 | V1 | V2 | 影响 |
|---|---|---|---|
| 工具名 | `tool` | `name` | 已按 `name` 解析 |
| 调用 ID | `callID` | `id` | 已兼容 |
| 状态 | pending/running/completed/error | **streaming**/running/completed/error | `streaming` 被当成 completed |
| 完成输出 | `state.output`(string) | **`state.content[]`** | 已部分处理 |
| 工具名 | `bash`/`task`/`apply_patch` | **`shell`/`subagent`/`patch`** | 特判失效，落到 else 显示原始 JSON |
| 路径入参 | `filePath`/`file_path` | **`path`** | read/write/edit 无路径、不可打开文件 |
| shell 入参 | `{command,...}` | `{command, workdir?, background?}` | 未区分 shell / shell background |

具体问题：
1. **shell 运行中不能展开看命令**：`toolSummary`/`shouldExpandRunningTool` 只匹配 `bash`。
2. **shell 显示成 JSON**：未识别 `shell`，走 else 显示 `args.take(60)`。
3. **shell background 无区分**：未读取 `input.background`。
4. **read/write/edit 不显示路径、不能打开文件**：读的是 V1 `filePath`。
5. **subagent / patch 未识别**：`task`→`subagent`、`apply_patch`→`patch`。

### P2 滚动
6. **不在底部时「跳到最新」按钮不可用**：`showScrollToBottom = !shouldFollow && canScrollForward`，与 `shouldFollow` 耦合导致误判。
7. **新消息不自动滚动到底部**：自动跟随触发不稳。

## 二、处理计划（模块 → 步骤）

### A. 工具 V2 渲染（`feature/session`）
1. 新增 `ToolArgs`（V2 专用）解析助手：读取 `state.status`、`state.input`、`state.content`、`state.metadata`。
2. `toolSummary` 重写为 V2 工具名：`shell`（含 `background` 区分）、`read`/`write`/`edit`（`path`）、`patch`、`subagent`、`glob`/`grep`/`webfetch`/`websearch`/`question`/`skill`。
3. `shouldExpandRunningTool`、`BlockToolLine`、`InlineToolLine`、`RunningToolLine` 统一按 V2。
4. `SessionMessageSearchPanel` 同步。
5. 状态映射补 `streaming → RUNNING`。

### B. 滚动（`feature/session`）
6. 「跳到最新」按钮显示条件改为「有内容在下方」（`canScrollForward`），不再依赖 `shouldFollow`。
7. 自动跟随：新消息/内容更新时，若应跟随则滚动到最新（用 `messages` 的最后一项 key 驱动，避免竞态）。

### C. 验证
8. Docker：Bridge + opencode v2 容器运行，触发 shell（含 background）、read/write/edit、patch 等工具。
9. 模拟器：`eip-test` AVD，检查工具展示/交互与滚动行为。

## 五、滚动问题 A/B 对照（2026-09-24）

对「新消息不自动滚动」做了 A/B 对照（Docker 发提示 + 模拟器检查新内容节点 bounds 是否进入可视区）：

| 版本 | 结果 |
|---|---|
| A：原始逻辑（`scrollVersion` + `needFollowScroll` + 索引 `size`） | 3/3 自动滚到底 ✅ |
| B：改动版（显式 effect + 索引 `size-1`） | 1/3 |

**结论**：滚动问题**未复现**，原始逻辑 A 是可靠的；改动版 B 反而更差（两次新内容未进入可视区）。因此**回退 B6/B7 到原始逻辑**。

## 六、新消息送达排查（2026-09-24）

针对“新消息偶发不显示”，直接读取模拟器 App 的 Room DB 核对：

- `sync_state`：`lastSeq=239`、`lastTimeUpdated=1790257449436`（与 opencode 同步推进一致）。
- `session_message`：B1/B2/B3 的 user/assistant 消息**全部存在**。

**结论**：**不存在“丢消息/不送达”问题**，增量同步已正确落库。此前“看不到”是滚动（新内容在视口外未 compose）。

**遗留（潜在、未观测）**：Bridge `/messages` 以 `time_updated > since ORDER BY time_updated ASC LIMIT 100` 分页，而 `time_updated` 非唯一；若同一毫秒的消息恰好跨在分页边界，可能被跳过。本数据集未命中（相邻消息相差 1–2ms）。建议后续改为 `(time_updated, id)` 复合游标以彻底消除。

## 七、最终决策

- 工具渲染：按 V2 统一（shell/background、read/write/edit 用 `path`、patch/subagent、streaming）。
- **diff vs 打开文件**：`isDiffTool = edit || patch`；`read`/`write` → 打开文件；`edit`/`patch` → diff（保持原设计，不加额外入口）。
- 滚动：**回退 B6/B7 到原始逻辑**。
- 新消息送达：无需改动（已确认正常）。


## 八、V2 工具/消息类型补充（2026-09-24）

参考 opencode TUI/web（`packages/session-ui/src/tools/tool-renderer.tsx`，`execute` 按 shell 风格渲染）补齐 V2 独有内容：

- **`execute`（CodeMode）**：按 shell 风格（等宽）渲染；折叠摘要优先显示其调用的工具（`metadata.toolCalls`，如 `search(query=…)`），无则显示代码首行；展开显示完整代码 + 输出。（原实现把原始 JSON 直接当一行，已改）
- **`synthetic` 消息**：后台 shell 完成通知（`metadata.source=shell`），渲染为 `shell + 命令 + · completed` 一行。
- **`skill` 消息**：显示技能名称。
- **`shell` 消息**：独立 shell 生命周期记录，渲染命令 + 状态。

**不支持**（按用户判断放弃）：`model-switched` / `agent-switched` / `location-switched`（模型已在用户消息下方显示）、`system`、`idle`。
