# OpenMate V2 对接进展

> 更新时间：2026-08-07

## 测试环境

- **opencode2**：安装在 WSL（Ubuntu）中，通过 `opencode2 service start` 运行，端口 4098
- **Bridge**：编译为 Linux musl 二进制，运行在 WSL 中，端口 4097
- **Android 模拟器**：通过 `10.0.2.2:4097` 访问 WSL Bridge
- **模型配置**：讯飞 provider（`xunfei/xopdeepseekv4flash`）+ z.ai provider + opencode 免费 provider

## 已完成

### Bridge V2 适配

1. **SSE 代理**：`/global/event` → `/api/event` + Basic Auth 注入 ✅
2. **REST 代理**：`do_proxy()` 自动注入 V2 Basic Auth header ✅
3. **DB 路径**：`opencode.db`（V2 实际使用的文件名，非 `opencode-next.db`）✅
4. **密码获取**：三层 fallback — bridge.db → `service.json` → `password` 文件 ✅
5. **进程管理**：改为通过 `opencode2 service start/stop/restart/status` 管理，不再直接 spawn `opencode2 serve` ✅
6. **崩溃检测**：从 `child.wait()` 改为定时 health check（daemon 模式无子进程可监控）✅
7. **auto-restart**：health check 连续失败 3 次后执行 `service restart` ✅
8. **revert 支持**：`get_deleted_message_ids()` 检测 revert 删除 ✅
9. **增量同步**：`get_messages_since()` 从 `session_message` 表读取，按 `time_updated` 增量 ✅
10. **OPENCODE_EXPERIMENTAL 清理**：移除了所有设置该环境变量的代码 ✅

### Android V2 适配

1. **API 路径**：全部 V1 路径 → V2 `/api/*` 路径 ✅
2. **JSON 反序列化**：`getV2Data`/`getV2List`/`postV2Data` 使用 `json` 实例（`ignoreUnknownKeys=true`）而非 `Json` companion object ✅
3. **SSE 事件解析**：V2 `{id,type,data}` 格式 + `session.*` 事件类型 ✅
4. **EventDispatcher**：适配 `session.*` 事件（text/reasoning/tool/step/compaction/shell/revert/input/execution）✅
5. **Provider/Model**：
   - V2 拆分为 `/api/provider` + `/api/model` 两个端点
   - `getProviders()` 同时请求两个端点，合并为 `ProviderListDto`
   - 新增 `V2ModelInfoDto` / `V2ModelVariantDto`（variants 从数组转 Map）
6. **Permission/Question**：
   - `PermissionDto` 字段重命名：`permission→action`、`patterns→resources`、`always→save`、`tool→source`
   - SSE 事件处理兼容 `permission.v2.asked` 和 `permission.asked`
   - Question 结构不变，事件类型兼容 `question.v2.asked`
7. **Prompt 发送**：
   - V2 用 `{text: "..."}` 替代 V1 的 `{parts: [{type:"text", text:"..."}]}`
   - model/agent 通过独立 session 级 API 设置（`/api/session/{id}/model`、`/api/session/{id}/agent`）
8. **Todo API**：V2 无 todo 端点，404 时返回空列表
9. **DTO 适配**：`HealthDto`、`SessionDto`、`ProviderInfoDto`、`AgentDto`、`SkillInfoDto`、`PathInfo` 等
10. **模型选择器 fallback**：`selectedModel == null` 时显示 "Select Model" 可点击占位

## 待解决

### V1/V2 DB 共存问题

V2 opencode2 使用 `~/.local/share/opencode/opencode.db`（与 V1 同名同路径）。在 WSL 环境中：

- `session` 表：V1 和 V2 的 session 混在一起（V1 有旧会话数据）
- `message` + `part` 表（V1 格式）与 `session_message` 表（V2 格式）共存
- `event` 表：`aggregate_id` 只有一个旧 session（`ses_029d0af73ffe...`），新创建的 V2 session 的事件没有写入 event 表
- `session_v2` 表：有 6 条记录

**影响**：
- Bridge 的 `get_messages_since()` 读 `session_message` 表是正确的（V2 写入）
- Bridge 的增量同步读 `event` 表可能取不到新 session 的事件（需确认 V2 事件是否写入 event 表）
- event 表的 `event_sequence` 机制需要确认 V2 行为

**需要确认**：
1. V2 是否仍然向 `event` 表写入？还是用了新的机制？
2. 如果 V2 不写 event 表，Bridge 的 SSE event source 和增量同步需要改为只依赖 `session_message.time_updated`

### `service.json` 密码管理

- `opencode2 service set password "xxx"` 可以设置密码，写入 `~/.local/state/opencode/service.json`
- Bridge 从 `service.json` 自动读取密码 ✅
- 但 `opencode2 service set port/hostname` 命令在 Bridge 启动时调用失败（npm postinstall warning），不影响功能因为 service 已预先配置好

### bridge.toml 应移除

`bridge.toml` 配置文件已不生效（Bridge 读 bridge.db，不读 toml）。应该：
1. 删除项目中的 `bridge.toml` 相关文档和示例
2. 更新 `AGENTS.md` 中的配置说明
3. 或让 Bridge 启动时将 toml 值写入 DB（当前 bridge.db 重建后用默认值，toml 的值被忽略）

### `opencode-next.db` 空文件

Bridge 默认 DB path 是 `opencode-next.db`（来自 Docker 测试时的发现），但实际 V2 用的是 `opencode.db`。`default_db_path()` 函数应改为 `opencode.db`。

### 发送消息后 AI 回复为 error

讯飞模型 `xopdeepseekv4flash` 在测试中返回 `"finish":"error"`，`error.type` 需要检查具体原因（可能是 API key 过期或模型限制）。但消息发送流程本身是成功的。

### 其他待适配项

- `getSessionStatuses()` 调用 `/api/session/active` 返回 500（V2 格式可能不同）
- `refreshRetryStatus()` 依赖 `getSessionStatuses()`，也受影响
- `/api/session/{id}/todo` 端点不存在（V2 无 todo），当前返回空列表
- `createSession()` 未传 model/agent（V2 支持在创建时指定，当前依赖后续 `setSessionModel`）
